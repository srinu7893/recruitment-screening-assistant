01 / Business problem

Reduce repeated work.
Keep the reason behind the decision.

Fragmented intake

Resumes arrive through files and source systems. Review context is easily separated from the original document.

Repeated reading

Reviewers repeatedly look for the same job requirements and reconstruct follow-up questions.

Unclear ownership

Teams need to know which profiles are waiting, who owns the review, and what changed.

Our response: one intake-to-review record with approved criteria, source evidence, ownership and decision history.

Business hypothesis, not measured customer results2 / 12

02 / End-to-end workflow

One visible path from incoming file to review.

1. Approve roleVersion job criteria and follow-up questions.
2. ReceiveUpload, paste or import an approved source.
3. Scan + extractCheck upload safety and extract readable text.
4. Queue + matchBackground worker finds quoted phrases and source lines.
5. Review + trackInspect context, correct evidence, add notes and record a decision.

What persists

Role versions, extracted source text, jobs, assessments, assignments, notes, scorecards, decisions and audit events.

What a reviewer sees

Processing state, evidence gaps, source excerpts and the team’s review history in the same workspace.

Original uploaded binaries are processed; retained extracted text is the review source3 / 12

04 / Matching logic

Show the evidence. Keep interpretation with people.

Approved criterion

Hands-on support using "Linux"

Resume line

“Used Linux logs and service commands to investigate failed requests.”

Result

Partial evidence + exact source excerpt + follow-up question.

What the rules do

  • Case-insensitive literal phrase matching with word boundaries.
  • Preserve exact source lines.
  • Report absent evidence as not_demonstrated.
  • Validate evidence against the source text.
Important example: “No hands-on Docker experience” still contains a literal mention. The engine marks it partial; a reviewer must read the quoted context. It does not infer years, proficiency, synonyms or qualification equivalence. All five untouched sample profiles route to clarification.
Evidence coverage is not a candidate quality score or automated rank5 / 12

07 / How we developed it

Build the workflow, then harden and verify it.

  1. Defined the contract: approved role versions, evidence excerpts, assessment states and separate human decisions.
  2. Built the workspace: intake, jobs, review pipeline, notes, assignments, scorecards, comparison and audit.
  3. Added automation: persisted settings, intake history, retries, deduplication and worker leadership.
  4. Adapted to available infrastructure: Cloud Run containers, an isolated Neon schema and Secret Manager.
  5. Simplified access and removed API dependency: normal password login and conservative local evidence matching.
  6. Verified the release: backend, PostgreSQL, browser, extraction, scanner and container checks, followed by a live synthetic smoke test.
Incremental implementation with versioned changes and repeatable checks8 / 12
